## Resolved 2026-07-04 (workflow simplification)

User-directed simplification pass after reviewing ceremony in the workflow. Applied to `DESIGN.md`, `TERMINOLOGY.md`, `SCHEMAS.md`, `WALKTHROUGH.md`, `IMPLEMENTATION-PLAN.md`, `OPEN-ITEMS.md`, and `README.md`.

- **Spec-card approval verbs made explicit** — the card now teaches `go` (approve and start) and `approve only` (approve without starting), plus `revise:`, `split:`, and `cancel`. Natural variants can map to those when unambiguous, but ambiguous prose defaults to `approve only`. This replaces documenting "looks good" / "looks good, go" as primary paths, which was too subtle for a binding gate.
- **`speccy review` made state-aware** — `review` now means "show the current human packet for this spec": spec card/approved summary before a run, status while running, review packet when verified, escalation packet when escalated, submitted close-out card when awaiting merge, and accepted summary after landing. `--evidence` remains the ledger/artifact/full-diff drill-down.
- **Close-out ceremony reduced** — `/speccy-ship` records a `change_ref`, and routine `speccy accept` uses that stored reference rather than requiring `--pr` or a spec ref when the submitted run is unambiguous. `accept` is idempotent after landing, displays the recorded change reference before recording, and remains a human assertion so teammate merges, squash merges, branch deletion, or base-branch movement do not break close-out. Accepted specs leave default status/list immediately; `archive` is no longer routine close-out and is reserved for stale historical context.
- **Selector inference promoted to the normal path** — human examples now use omitted selectors for the common unambiguous case: `speccy review`, `/speccy-ship`, and `speccy accept`. Full `SPEC-...` references remain exact selectors for ambiguity, scripts, CI, and durable PR metadata. This makes the workflow feel spec-first without forcing users to type generated IDs during routine use.
- **`/speccy-plan` gained route preflight** — direct invocation no longer assumes the user has chosen the full Speccy workflow. It first classifies the request with the same route vocabulary as brainstorm; tiny direct edits, normal harness-plan work, and split-worthy initiatives route away without `spec start`, task graph, ledger, or run state. A user can still explicitly say "use Speccy anyway" to override. This moves "when to use Speccy" from user education into the skill's default behavior.
